# Phase F — Operable (`cloved`, `clove`)

**Status:** In progress. This pins the API surface, the daemon/CLI shape, the
persistence plan, and the TUI decision before the daemon wiring is written, so
the architecture is agreed up front. Maps to `PLAN.md` Phase F and milestone M4
(daily-drivable daemon + CLI). Nothing here relaxes `SCOPE.md` §9 — in
particular the ≤15-dependency budget and the hand-roll list (HTTP/1.1 both
ends, JSON, arg parsing) stand.

## 1. Architecture

```
clove (CLI)  ──unix socket (default) / loopback TCP (opt-in)──▶  cloved
                          HTTP/1.1 + JSON, /v1/                    │
                                                                  ▼
                                    engine host (torrent registry, persistence)
                                                                  │
                                                                  ▼
                                                     i2pnet (SAM) ── router
```

- **`cloved`** loads config, opens the data dir, hosts the engine (a registry
  of `Torrent`s), and serves the `/v1/` API. One blocking accept loop, one
  thread per API connection (Q5 discipline; API load is tiny).
- **`clove`** is a thin client: hand-rolled arg parsing, one request per
  invocation, renders an aligned table by default or JSON with `--json`.
- **Every socket-construction site stays in `i2pnet`** (SCOPE §5). `cloved`
  gets a listener *handle*, never a socket API. A new `i2pnet` helper binds
  either a unix socket (default) or a **loopback-validating** TCP listener
  (opt-in), refusing any non-loopback address. The unix socket is not an IP
  socket and carries no clearnet-leak risk; the TCP option is the one that
  needs the loopback guard.

## 2. Transport & wire format (foundation — landed)

- **HTTP/1.1**, hand-rolled, both ends, in `clove-core::http` (Q6). The server
  half — `read_request` + `Response::encode` — landed alongside this doc,
  reusing the existing client parser; unit-tested over cursors.
- **JSON**, hand-rolled *encoder only* in `clove-core::json` (no serde).
  Commands reach the daemon as method + path + small typed bodies, so no JSON
  *parser* is needed. Landed with this doc.
- No chunked encoding, no keep-alive: one request, one `Content-Length`
  response, connection closed.

## 3. API surface (`/v1/`)

JSON responses; token auth via an `X-Clove-Token` header (required on the TCP
listener, honored on the unix socket too). Read commands take `?json` implicitly
(the API is always JSON; the CLI decides table vs. raw). Proposed endpoints:

| Method & path | Purpose |
|---|---|
| `GET /v1/status` | daemon + router state (version, uptime, SAM/"waiting for router", totals) |
| `GET /v1/torrents` | list: info-hash, name, state, progress, up/down rates, peers |
| `GET /v1/torrents/{ih}` | one torrent in detail (files, priorities, trackers, peers) |
| `POST /v1/torrents` | add by `.torrent` (body) or magnet (body); returns the info-hash |
| `DELETE /v1/torrents/{ih}` | remove; `?data=1` also deletes downloaded data |
| `POST /v1/torrents/{ih}/pause` · `/resume` · `/verify` · `/announce` | lifecycle actions |
| `PUT /v1/torrents/{ih}/priorities` | set per-file priorities |

Errors are a JSON `{ "error": "…" }` body with an accurate status (400 bad
input, 401 bad/missing token, 404 unknown info-hash, 409 duplicate add).

## 4. CLI (`clove`)

Subcommands map onto the endpoints: `add` (file/magnet), `remove [--data]`,
`list`, `status <ih>`, `pause`/`resume`, `verify`, `priorities`, `announce`,
`stats`. Rules (SCOPE §3):

- Aligned-table human output by default; **`--json` on every read command**
  (the raw API body) for scripting.
- Sensible exit codes: `0` ok, `1` operation failed, `2` usage error, `3`
  daemon unreachable.
- Shell completions generated by a hidden `clove completions <shell>` command
  (hand-written generators — no clap).
- Wire identity stays `-CV0001-` / `clove/0.1` (Q7), re-checked before M3.

## 5. Persistence

- Resume writer reaches its final on-disk form here: atomic write-temp-rename
  (SCOPE §3), the bencode format from Q2, integer `version` from day one.
- **`STATE-FORMAT.md`** is written alongside it — the format is an API (SQLite
  doctrine): newer clove reads older state; older clove refuses newer state
  cleanly.
- The API token is generated once (via `getrandom`, the one new Phase-F dep,
  already approved in `DEPENDENCIES.md`) and persisted in the data dir with
  `0600` perms.

## 6. The TUI question — decision

**No TUI framework.** A full-screen framework (`ratatui` + `crossterm`) is
rejected on `SCOPE.md` §9 grounds: it would roughly double the dependency tree
(crossterm/unicode-width/bitflags/signal-hook/…), break the human-reviewable
`cargo vendor` goal, and add a large raw-mode/input/resize surface to audit —
`yosemite` already spent the proc-macro budget, and the spec asks for "aligned
tables, progress, rates," not a full-screen app.

**What we build instead:** a `clove watch` subcommand — a live, glanceable view
that repaints the same aligned status table on an interval using a handful of
ANSI escapes (clear + home-cursor), **no raw mode, no framework, zero new
dependencies**. A built-in, prettier `watch -n1 clove status`, reusing the exact
table renderer the plain commands use. This honors "300 focused lines over
30,000 imported" and delivers the live-view value without the cost. It lands
last (§7), after the plain commands, since it is just a redraw loop over `list`.

If a full curses-style UI is ever genuinely wanted, it is a separate,
budget-spending decision — not smuggled in with M4.

## 7. Build order (incremental, each tier-1-green)

1. **Foundation — landed:** HTTP/1.1 server primitives (`http`) + JSON encoder
   (`json`), both unit-tested, no new deps.
2. **Transport slice — landed:** `i2pnet::api` (unix + loopback-validating
   TCP), a `cloved` that loads config, generates a `0600` token, and serves
   `GET /v1/status` with token auth (one thread per connection), plus
   `cloved -C` and `clove status`. Proven end to end over a unix socket, no
   router needed. `clove` prints the raw status JSON for now — human table
   rendering waits on the JSON parser in step 3.
3. **Engine host + JSON parser**: a hand-rolled JSON *parser* (so `clove`
   renders aligned tables, `--json` passing the raw body); torrent registry,
   `add`/`list`/`remove`, resume persistence + `STATE-FORMAT.md`.
4. **Remaining commands**: detail view, pause/resume/verify/announce,
   priorities, stats; completions; `cloved -C` config check.
5. **`clove watch`**: the hand-rolled live view (§6).

Layer-2 self-restriction (Landlock/seccomp) and man pages are Phase G, not here.
