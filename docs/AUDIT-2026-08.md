# Security audit, 2026-08

A full read of clove at `e9c5fd8`: every crate, the CI gates, the systemd
units, and the install path. Written against the project's own threat model
(`SECURITY.md`), because that is what a finding has to be measured against —
three of the five findings below are places where a guarantee that file makes
did not hold.

The five are fixed in the same change as this file. The observations after
them are not fixed: each is a trade-off with a reason on both sides, and the
decision is the maintainer's.

## Summary

| # | Finding | Severity | Status |
|---|---------|----------|--------|
| F1 | Terminal control and bidi characters survive the JSON encoder, so `--json` output is not inert in a terminal | Medium | Fixed |
| F2 | The `rustix` `net`-feature CI gate could not see the manifest form the workspace uses | Medium | Fixed |
| F3 | BEP 27 `info.private` was parsed and reported but never enforced; peer exchange ran on private torrents | Medium | Fixed |
| F4 | No bound on a torrent's announce URLs, all of which the announcer walks in series | Low–Medium | Fixed |
| F5 | The control socket was connectable at its final name before it was made owner-only | Low | Fixed |

No memory-safety defect was found, and none was expected: `unsafe_code =
"forbid"` holds across the workspace, and the one crate that needs syscalls
std does not expose reaches them through `rustix` rather than by hand.

## F1 — Terminal hazards survive the JSON encoder

**Where.** `crates/clove-core/src/json.rs`, `write_string`.

`SECURITY.md` promises that foreign text is scrubbed "where it becomes a
terminal's input, in the daemon's log lines and in `clove`'s output alike",
and `crate::text`'s module documentation names the exact set that matters:
the `Cc` category — C0, `DEL` **and C1** — plus the bidirectional overrides
and isolates.

The encoder escaped characters below `0x20` and nothing else. `DEL`
(`U+007F`), the C1 controls (`U+0080`–`U+009F`) and every bidi override
passed through as literal UTF-8. That would be fine if JSON only ever reached
a parser, and `text`'s documentation says as much — but three CLI paths print
the daemon's JSON straight to the terminal:

- `clove status --json` (`crates/clove/src/main.rs:341`)
- `clove list --json` (`:354`)
- `clove show --json` (`:457`)

None passes through `display`/`scrub`. A torrent named
`safe\u{202e}gnp.exe` therefore rendered in the operator's terminal as
`safe.exe.gnp`, inside a JSON string exactly as outside one — the spoof
`text::scrub` exists to stop, on the output path that skipped it.

The gap was already half-known: the CLI's own error path carries a comment
saying that `json::write_string` escapes everything below `0x20` "so the
escape sequences cannot survive the daemon's encoder, **but the bidirectional
overrides can and do**" — and scrubs there. The `--json` paths were not
given the same treatment.

**Fixed** by escaping the whole `text::scrub` set as `\uXXXX` in the encoder
rather than by scrubbing at the three call sites. RFC 8259 permits escaping
any character, so the output is still valid JSON and a consumer that
unescapes gets the torrent's real name back — which is the property
`SECURITY.md` promises for the API. A terminal is shown six inert ASCII
characters instead.

## F2 — The `net`-feature gate could not see `cloved`'s manifest

**Where.** `ci/check-net-deps.sh`.

`rustix` is in the tree for `openat` and is the one allowlisted crate that
*could* open a socket — its `net` module is one word in a `Cargo.toml` away.
`DEPENDENCIES.md` says the script "also fails if any manifest turns the `net`
feature on", and that "that check is per-manifest, so it covers `cloved`'s
use as well".

The check was:

```sh
if grep -n '^rustix' "$manifest" | grep -q '"net"'; then
```

which reads one line: the line the crate name is on. `crates/cloved/Cargo.toml`
has declared rustix's features across six lines since it acquired its third
feature:

```toml
rustix = { version = "1", default-features = false, features = [
    "fs",
    "process",
    "rand",
    "std",
] }
```

so `"net"` added to that list is two lines below anything the gate looks at.
Confirmed by adding it and running the gate, which printed
`check-net-deps: ok` and exited `0` — the daemon's own manifest, which is the
one that matters, was the one manifest the check could not read.

**Fixed** with an `awk` scanner that reads the whole declaration in all three
TOML spellings (bare value, inline table on one line or many, and
`[dependencies.rustix]` as its own table), and a `--self-test` mode that
checks the scanner against manifests written to trip it. CI runs the
self-test before the gate: a scanner that silently stopped matching would
otherwise report `ok` for every run after the one that broke it.

## F3 — `info.private` was enforced nowhere

**Where.** `crates/clove-core/src/torrent.rs`.

`MetaInfo::private` was parsed (`metainfo.rs:243`), stored, and reported by
`GET /v1/torrents/<hash>` (`registry.rs:1847`). Nothing else read it. The
engine never received the flag at all: `Torrent`'s shared state had no field
for it.

So a private torrent ran peer exchange exactly as a public one does —
`our_extension_handshake` advertised `i2p_pex` unconditionally, `send_pex`
handed the torrent's address book to any peer that offered an id for it, and
inbound `i2p_pex` messages were accepted and folded into the known-peer set.

BEP 27's rule exists because a private tracker decides who is in the swarm,
and peer exchange makes that decision on its behalf. On I2P the consequence is
sharper than on the clearnet: a destination is not an IP address that a
tracker would rather not publish, it is the whole of how to reach that peer.
Handing one to any party that completes a handshake is "leaking … a peer's
[destination] to somewhere it does not belong" — `SECURITY.md`'s leak class,
the highest severity the project recognises.

**Fixed** in both directions. A private torrent does not advertise `i2p_pex`,
does not record a peer's id for it, and ignores the message if one arrives
anyway. `ut_metadata` is untouched: BEP 27 restricts where *peers* may come
from, and metadata is the torrent both sides already hold.

`crates/clove-core/tests/evil_peer.rs::a_private_torrent_speaks_no_peer_exchange`
covers it end to end over the mock network, and fails on the code as it stood.

Note for review: the unit-test fixture in `torrent.rs` builds its `MetaInfo`
with `private: true`, so the flag has been sitting in the tests all along with
nothing asserting on it. The integration fixtures build a real bencoded info
dictionary with no `private` key, which is why nothing caught this.

## F4 — A torrent decides how many trackers the daemon announces to

**Where.** `crates/clove-core/src/metainfo.rs` (`parse_trackers`),
`crates/cloved/src/registry.rs:799`, `crates/clove-core/src/swarm.rs`
(`announce_loop`).

`parse_trackers` kept every I2P announce URL a torrent offered, with no
ceiling. The registry flattens all tiers into one list, and the announcer
walks that list in series, resolving a name and dialling each entry with
timeouts measured in the minute (`ANNOUNCE_DEADLINE` is 120 s, and so is the
dial timeout). Tier semantics are a documented simplification; the missing
bound is not.

Bencode is compact, and the API accepts a two-megabyte body: that is room for
something on the order of a hundred thousand `http://a.i2p` announce URLs in
one `.torrent`. Two consequences, both from a file a stranger wrote:

- The announcer's first pass does not finish in any useful time, so the
  tracker the torrent is actually on is announced to once and then not again
  for days. `SECURITY.md` puts hangs triggered by a `.torrent` in scope.
- Each URL is one more party told the client's full destination, since that
  is what an announce carries as `ip`.

**Fixed** with a cap of 16 tiers by 16 URLs — generous against reality (I2P
torrents carry one or two trackers) rather than against the format. Excess
URLs are counted like any other dropped announce URL.

While fixing it: `skipped_trackers` had no reader anywhere in the tree,
despite its documentation saying callers may log it. A torrent that quietly
lost trackers left the operator to work it out from having no peers. The
count — and only the count, never the URLs, per SCOPE §3 — is now logged when
a torrent is added.

## F5 — The control socket was reachable before it was restricted

**Where.** `crates/i2pnet/src/api.rs`, `ApiListener::bind_unix`.

The listener was bound at its final path and the mode set afterwards:

```rust
let listener = UnixListener::bind(path)?;
std::fs::set_permissions(path, Permissions::from_mode(0o600))?;
```

`bind(2)` creates the socket with `0777 & ~umask`, which is `0755` under the
umask a shell hands out. Between those two lines a connectable socket exists
at exactly the name a client looks for, with the permission not yet taken
away.

This is the second lock rather than the first: token auth means a local user
who won the race is answered `401` and nothing else, the default
`api_socket` sits in `$XDG_RUNTIME_DIR` or the `0700` data directory, and both
systemd units set `UMask=0077`, which closes the window outright. What is left
is a hand-started daemon whose `api_socket` is configured into a shared
directory.

**Fixed** by binding under a temporary name in the same directory, setting the
mode, and renaming into place — the discipline `write_private_file` already
uses for the token and the destination key. Renaming a bound socket keeps the
listener, since the socket lives in its inode and the path is only a name to
resolve; the rename is atomic, so it also removes the moment of "no socket at
all" that unlink-then-bind left between runs.

## Observations — reported, not changed

**O1. The SAM forwarded-listener port is an unauthenticated local ingress.**
`SamListener::forward` binds `127.0.0.1:0` and asks the router to
`STREAM FORWARD` there. `accept()` then reads whatever destination line the
connecting process sent, and any local process — any uid on the machine — can
connect to that port and supply one. With an info-hash the daemon hosts (a
guess, for a public torrent), a local user can join the swarm as a peer of
their choosing: confirm the torrent is hosted, take a connection slot, and, on
a non-private torrent, receive the address book over PEX. The code is aware
that anything can produce such a connection — it says so where it drops the
ones it cannot parse — but the consequence is not written down anywhere.

This is inherent to `STREAM FORWARD`, not a coding error: SAMv3 offers no
authentication on the forwarded channel. `STREAM ACCEPT` does not have the
problem, because the router uses a socket clove itself opened to the bridge.
That is a real design change with its own costs (an accept slot per pending
connection). The cheaper half is to say so: `SECURITY.md`'s out-of-scope list
covers "an already-compromised machine or the daemon's own user account", and
a *different* local account is neither.

**O2. `clove` reads the API token without the checks `cloved` applies to it.**
`resolve()` (`crates/clove/src/main.rs:1171`) is a plain `read_to_string`. The
daemon's `read_private_file` refuses a token that is a symlink, is not a
regular file, is owned by another uid, or carries group/other permission bits,
and tells the operator to delete it — reasoning the CLI does not share, so it
will happily read and send a world-readable token. Not a privilege boundary
(both run as the same user), but it means the "this secret has been readable
by others" warning fires only when the daemon restarts. Lifting
`read_private_file` into a place both binaries can call would make the two
agree.

**O3. Release builds keep wrapping arithmetic.** There is no
`[profile.release] overflow-checks`, so integer overflow wraps in the shipped
binary. This is consistent with SCOPE §9's "release builds stay lean, debug
builds are dense with invariant assertions", and it is recorded here only so
the trade-off is explicit rather than incidental. I found no reachable
overflow: the parsers and the piece arithmetic use `checked_*` and
`saturating_*` consistently, and the products that matter (piece index by
piece length, metadata piece by 16 KiB) are computed in `u64`/`usize` with
inputs bounded well below the type.

**O4. CI actions float on major tags.** `actions/checkout@v4`,
`actions/cache@v4`, `actions/upload-artifact@v4` and
`EmbarkStudios/cargo-deny-action@v2` are mutable references. The blast radius
is small — the workflow declares `permissions: contents: read`, uses
`pull_request` rather than `pull_request_target`, and exposes no secrets — but
pinning to commit SHAs costs nothing and is the standard hardening. The `deny`
job is also the one job with no `timeout-minutes`.

**O5. `RuntimeDirectoryMode=0755`** leaves `/run/clove` world-traversable in
the system unit. Nothing rests on it: the socket inside is `0600` and owned by
the `DynamicUser` uid, so traversal grants nothing, and `0700` would lock an
operator out of a system-wide daemon entirely. No change recommended — noted
so it is clear that the socket's mode is doing all of the work.

## Reviewed and found sound

The larger part of an audit is what it does not find, so: the following were
read closely and no defect was found in them.

- **Parsers.** Bencode (depth limit, strict integer and length syntax,
  duplicate keys refused, lengths checked against remaining input before
  allocation), metainfo, the peer wire codec, the extension handshake,
  `ut_metadata`, `i2p_pex`, tracker responses, magnet URIs, resume files, JSON,
  and both directions of HTTP. Every declared length is validated before it
  sizes an allocation. Ten fuzz targets cover this surface, with dictionaries,
  a committed seed corpus and per-target budgets.
- **Path handling.** `metainfo::check_component` refuses separators, `.`, `..`
  and NUL; `storage::walk_beneath` then declines to trust that, walking each
  component as a directory descriptor with `O_NOFOLLOW` so a symlink is the
  kernel's refusal rather than a check that could be stale. Deletion under
  `--data` uses the same walk. Colliding and prefix-shadowing file paths are
  refused at parse time.
- **The peer protocol under hostile control.** Block writes require the block
  to have been solicited, to match the expected length exactly, and to belong
  to a piece not already held; a completed piece is verified from disk before
  it is announced or served. Requests are bounded inside the piece they name,
  not merely inside the torrent. Repeated bitfields and have-alls withdraw
  what the previous set contributed, so availability cannot be inflated.
  `MAX_CONNECTIONS_PER_DEST`, the client-wide peer budget and
  `MAX_PENDING_HANDSHAKES` all hold.
- **The local API.** Token auth precedes routing and runs on every request,
  including the ones that do not exist; the comparison is constant-time and
  refuses a token that is not exactly 64 hex characters, so an empty stored
  token cannot match an empty header. The transport is a unix socket only.
  Info-hashes in a path are 40 lowercase hex characters or nothing, so a path
  segment is never a filename. Request bodies are capped, a second
  `Content-Length` is refused rather than resolved, and `Transfer-Encoding` is
  refused outright.
- **Secrets.** The token and the destination key are written `0600`
  temp-then-`fsync`-then-rename, and read back through `O_NOFOLLOW` plus an
  `fstat` on the descriptor actually held — refusing, rather than repairing, a
  file that is a symlink, is not regular, has the wrong owner, or is readable
  by anyone else. The data directory is forced to `0700` on every start, fatally
  if that fails. The distinction between the public destination and the private
  key blob behind it is enforced by `destination_len`, fuzzed, and load-bearing
  in a way the project has already been bitten by.
- **The I2P boundary.** No socket type outside `i2pnet`; no IP vocabulary in
  the engine, enforced by clippy type bans; SAM addresses restricted to
  loopback at config parse with no override; no DNS path; non-I2P announce
  URLs dropped at parse time and never logged. `NAMING LOOKUP` names and
  `STREAM CONNECT` destinations cannot carry a space or a control character
  into the line protocol — checked in `i2pnet` rather than assumed of the
  parser two crates away.
- **The sandbox.** The seccomp allowlist is measured from a traced run and
  re-checked by `ci/router.sh --trace` on every CI run, so it cannot rot
  silently. `socket(2)` is restricted to `AF_INET`/`SOCK_STREAM`, closing the
  datagram path Landlock's TCP rule cannot reach; `ioctl(2)` to `FIONBIO`,
  leaving no route to `SIOCGIFCONF`; `mmap`/`mprotect` enforce W^X. Landlock
  grants each path the rights that kind of directory needs, with `Execute` and
  `MakeSym` deliberately absent. Confinement is applied before any thread is
  spawned, which is what makes the domain cover the ones that follow.
- **Dependencies.** Nine direct dependencies, each justified in
  `DEPENDENCIES.md`, all current, none socket-capable in the configuration
  used. `cargo-deny` runs in CI over licences, advisories, yanked crates and
  wildcard requirements.

## Verification

```console

$ cargo clippy --workspace --all-targets -- -D warnings
$ cargo test --workspace
$ cargo check --manifest-path fuzz/Cargo.toml
$ ./ci/check-net-deps.sh --self-test && ./ci/check-net-deps.sh

```

`chaos.sh` skips its unwritable-state case when run as root, and Landlock is
absent from the container this audit ran in, so `router.sh` reported seccomp
installed and Landlock unavailable. Both are environment limits rather than
results.
