# clove — code quality and security audit

**Date:** 2026-09-02
**Commit audited:** `5e2c30f` (`main`, merge of PR #60)
**Scope:** every file in the repository: the four crates (`i2pnet`, `clove-core`, `cloved`, `clove`, ~32k lines of Rust including tests), the fuzz crate, the CI scripts, the systemd units, the man pages, and the design documents.
**Method:** full read of every source file by four parallel reviewers with the project's own threat model (`SECURITY.md`) as the checklist, every reported finding re-verified against the code by a fifth pass, plus the complete CI pipeline run locally (results below). No files were modified; this document is the only change.

---

## 1. Verdict

clove is in unusually good shape for a project of its age. The property it exists for, *no traffic outside I2P*, holds up under adversarial reading: the SAM port is the only thing ever dialled, it is dialled as a literal `127.0.0.1` by type rather than by string check, there is no DNS path anywhere, non-I2P trackers are refused by a single shared URL parser, and the private destination key is scrubbed on the way into every log line. The hostile-input parsers (bencode, metainfo, HTTP, resume, wire) are strict, bounded, and fuzzed. The local API's authentication is careful in exactly the places that usually go wrong.

**No Critical findings.** Nothing found lets clove contact a non-loopback address, leak the private key to a log or a peer, bypass the API token, or write outside the download tree.

**Three High findings**, all in the peer engine and all of the same shape: a single hostile peer can degrade a torrent for a long time without being detected or evicted. None is a memory-safety or leak issue, but all sit inside the threat model `SECURITY.md` declares ("remote crashes, hangs, or unbounded memory growth triggered by a peer" and "one peer destination cannot take over a torrent").

The Medium findings are mostly robustness gaps in error paths: an `accept(2)` error that quietly ends inbound service, a second daemon instance that can tear a resume file, a refused identity file that gets overwritten, and a `Debug` derive that would print the private key if anyone ever formatted the config struct.

## 3. Findings

Each finding has an ID, a severity, the location, what goes wrong, and a suggested fix. Locations are `file:line` at the audited commit. "Needs confirmation" marks the few items whose impact depends on something outside this repository.

### 3.1 High

**H-1. One destination can deny all inbound connections.**
`crates/clove-core/src/swarm.rs:652,721-724,742-770`; `crates/clove-core/src/torrent.rs:97`.
The pending-handshake cap (`MAX_PENDING_HANDSHAKES = 64`) is global. The per-destination cap is only checked *after* the 68-byte handshake has been read, and that read uses a per-syscall timeout of 60 s. An attacker opens 64 streams from one destination and sends nothing (or one byte every 59 s, which renews the timeout and stretches each hold to about 68 minutes). Every honest inbound stream is dropped at the cap for that duration. The `from` destination is known before the handshake, so the cap could be per-destination.
*Fix:* count pending handshakes per destination (at most `MAX_CONNECTIONS_PER_DEST`), give the handshake read an absolute deadline rather than a per-read timeout, and shorten the inbound handshake timeout. Add a test where one destination holds the cap *while* an honest peer connects; the existing `a_flood_of_silent_connections_does_not_wedge_the_demux` releases the flood first.

**H-2. A dribbling handshake stalls a torrent's whole dial sweep and blocks pause/shutdown for up to ~68 minutes.**
`crates/clove-core/src/torrent.rs:743-748`; `crates/clove-core/src/swarm.rs:130-135,568-588`; `crates/clove-core/src/pex.rs:24`.
Outbound `attach` uses the same per-read timeout. The dial sweep is a scoped worker pool that cannot return until every attach finishes, and `Swarm::shutdown` joins the dial thread. The stop flag is only checked between dials. PEX lets a peer hand us 512 destinations of its choosing, so it can arrange for the next sweep's eight slots to all land on hosts it controls that accept and dribble. No other peer is dialled for that torrent meanwhile, and pause, remove, and session rebuild all block on the join.
*Fix:* absolute deadline across the handshake exchange; on stop, close in-flight streams from the sweep rather than waiting for them.

**H-3. No hash-failure attribution: one garbage-serving peer can make a download burn bandwidth indefinitely.**
`crates/clove-core/src/torrent.rs:1288,1302-1312`; `crates/clove-core/src/picker.rs:369-375`.
When a completed piece fails SHA-1, the piece is reset and nothing is recorded about who supplied its blocks. The peer stays connected, interested, and unchoked; its pipeline is refilled in the same call; every arriving block resets its `strikes`; its destination stays `Trusted` in the known-peer set. With one honest seeder and one liar splitting a piece's blocks, a piece completes from honest bytes alone with probability 2^-N per attempt, and the wasted bytes count toward `downloaded`. This is a per-torrent hang by one peer, inside the stated threat model. The existing `corrupt_blocks_never_become_verified_pieces` test proves no false verification, then completes with a *fresh* leecher rather than bounding bytes-to-completion with the liar still attached.
*Fix:* record the supplying peer per block in `Progress`; on failure, if one peer supplied the whole piece, drop and ban it for the run (a `HashSet<DestHash>` consulted by both `sweep` and `route`); otherwise mark all contributors suspect and drop at a small threshold. Add a liar-plus-honest concurrent test with a bytes budget.

### 3.2 Medium

**M-1. A transient `accept(2)` error silently ends inbound peer service for the rest of the session.**
`crates/i2pnet/src/sam.rs:979-994`; `crates/clove-core/src/swarm.rs:735`; `crates/i2pnet/src/lib.rs:168-171`.
`SamListener::accept` propagates every error from `TcpListener::accept` and from `set_read_timeout`. The trait contract says `Err` means session loss, and the demux thread honours that by returning. But `EMFILE`/`ENFILE` (fd exhaustion), `ECONNABORTED`, `ENOBUFS`, and `ENOMEM` are not session loss. Any of them kills the accept loop while `clove status` keeps saying `connected`, and nothing rebuilds. Thread-per-peer plus one open fd per torrent file makes fd exhaustion reachable from a swarm.
*Fix:* treat those errnos (and a failed `setsockopt` on the accepted socket) as "this connection was not usable": drop it, sleep briefly on fd exhaustion, return `Ok(None)`. Reserve `Err` for `EBADF`/`EINVAL` on the listener, and on those end the session so the supervisor rebuilds.

**M-2. The same class of error exits the whole daemon on the API socket.**
`crates/cloved/src/main.rs:714-728`.
`serve` returns on the first accept error. Under `EMFILE` the daemon exits with "accept failed"; under `Restart=on-failure` it flaps, dropping every peer and re-verifying on each restart.
*Fix:* log, sleep ~100 ms, and continue on `EMFILE`/`ENFILE`/`ECONNABORTED`/`EAGAIN`; exit only on `EBADF`/`EINVAL`.

**M-3. No single-instance guard; a second daemon hijacks the socket and can tear resume files.**
`crates/i2pnet/src/api.rs:30-36`; `crates/cloved/src/registry.rs:2048-2055`.
`bind_unix` unconditionally unlinks whatever is at `api_socket`, including a live daemon's socket, and rebinds. There is no lock file or pidfile. Two daemons on one `data_dir` both persist every 30 s, and the registry's `atomic_write` uses a fixed temp name (`<path>.tmp`) opened with truncation, unlike `write_private_file` in `main.rs` which uses a pid-suffixed `create_new` temp. Daemon A writes and fsyncs, daemon B truncates and starts writing the same temp, A renames the half-written file into place. On the next start `Resume::decode` fails and the torrent silently disappears from the listing.
*Fix:* `flock(LOCK_EX|LOCK_NB)` on `<data_dir>/lock` before touching state or the socket, refusing to start if held. In `bind_unix`, probe with `connect()` and only unlink on `ECONNREFUSED`. Give `atomic_write` the pid-suffixed `create_new` temp the secret writer already has.

**M-4. A refused `destination.key` is destroyed and replaced, not preserved.**
`crates/cloved/src/main.rs:307-353`.
`Identity::load` refuses a key file that is world-readable, foreign-owned, or a symlink and starts a transient identity. `Identity::remember` then compares using plain `read_to_string`, sees a different key, and renames the new key over the old file. An operator who restores the data directory from an archive that dropped modes loses their stable identity permanently after one log line. The token in the same situation is fatal-and-preserve. The key is the more valuable of the two.
*Fix:* treat a refused key like a refused token (fatal, with instructions), or rename it aside before writing a new one. The existing test only checks `load()`, not that the file survives a subsequent `remember()`.

**M-5. `SamConfig` derives `Debug` over the field holding the full private key blob.**
`crates/i2pnet/src/sam.rs:350-368`.
`persistent_key` is the SAM `DESTINATION=` blob: public destination plus private encryption and signing keys. `SamSession` deliberately has no `Debug` and every router line is scrubbed before it can reach a log, but the config struct undoes that: one `{config:?}` in an error path would print the key to stderr or the journal. No current caller does this, so the finding is latent, but the type and field are `pub` and this is the class `SECURITY.md` ranks highest.
*Fix:* implement `Debug` by hand with the key redacted, or wrap it in a newtype whose `Debug` and `Display` are redacted and which does not implement `Clone`. Add a test that `format!("{config:?}")` does not contain the key.

**M-6. The forwarded-connection header read has a per-byte timeout but no overall deadline, on the single acceptor thread.**
`crates/i2pnet/src/sam.rs:983,1002-1022`.
`read_sam_line` takes a whole-exchange deadline precisely because a bridge dribbling one byte inside the read timeout could hold it open indefinitely. `read_dest_line` was not given the same guard: it reads byte-at-a-time under a 30 s `SO_RCVTIMEO`, so one byte every 29 s keeps it going for up to `MAX_DEST_LINE × 30 s`, roughly 34 hours, inside `accept()`, before any per-connection thread exists. The forward port is an unauthenticated loopback TCP port, so any other local user can do this; a remote peer cannot control the timing.
*Fix:* give `read_dest_line` an `Instant` deadline, or move the header read into the per-connection thread.

**M-7. (Needs confirmation of applicability) The `STREAM FORWARD` port accepts unauthenticated peer identities from any local process.**
`crates/i2pnet/src/sam.rs:898,979-994,1025`.
SAM's forward mode has no authentication: whoever connects to the loopback port and writes `<b64 destination> FROM_PORT=0 TO_PORT=0\n` is treated as an inbound stream from that destination. Another local user can present as arbitrary destinations, defeating the per-destination cap and filling pending-handshake and peer slots. Pieces are still hash-checked, so no data corruption. This is a property of SAM rather than a coding error, and `SECURITY.md` puts other local users in scope for the API but does not mention this surface.
*Fix:* document it as a known limitation on multi-user hosts. The clean technical fix is `STREAM ACCEPT` (authenticated by the SAM connection), which the module rejects for concurrency reasons; a middle path is one `STREAM ACCEPT` socket per pending connection.

**M-8. The BEP 27 `private` flag is parsed and reported but never honoured; PEX runs on private torrents.**
`crates/clove-core/src/metainfo.rs:243`; `crates/clove-core/src/torrent.rs:970,1186-1236`; `crates/cloved/src/registry.rs:1818`.
The only consumer of `meta.private` is the JSON output. `i2p_pex` is advertised in every BEP 10 handshake, inbound PEX is accepted, and the full known-peer list is sent to every peer. Private trackers treat that as a ban-worthy violation, and it lets a non-member reach the swarm. The doc comment itself says private is "common on I2P".
*Fix:* thread `private` into `Torrent`; when set, do not advertise `i2p_pex`, ignore inbound PEX, and never call `send_pex`.

**M-9. No cross-torrent path collision check; two torrents with the same `name` share files on disk.**
`crates/cloved/src/registry.rs:991-994`; `crates/clove-core/src/storage.rs:388-392`.
`add_torrent` rejects only a duplicate info-hash. Storage opens with `O_CREAT` but not `O_EXCL`. A different torrent with the same `name` and overlapping paths opens the same inodes; both engines write at different offsets, both fail verification forever, and the original data is silently corrupted. `check_distinct_paths` prevents exactly this *within* one torrent.
*Fix:* refuse (or suffix) a `name` already hosted; or lay each torrent out under `<downloads>/<infohash>/` and keep `name` cosmetic.

**M-10. Disk I/O and O(pieces) work run under the single torrent mutex, and cheap peer messages trigger it.**
`crates/clove-core/src/torrent.rs:1009-1027,1029,1130-1143,1162-1166,1295,1302,1335,1353,1376-1378`; `crates/clove-core/src/picker.rs:313-315,458-503`.
Under the lock: `write_block`, `verify_piece` (up to 128 MiB of SHA-1), `read_block` per request. Per *any* message including a 4-byte keep-alive: `is_complete` is O(n) whenever no wanted piece is missing, which is every seeder forever. Per 5-byte `HaveAll`/`HaveNone` (accepted although fast is never negotiated): two O(n) passes plus `update_interest`. Per arriving block: `in_endgame` O(n) plus a sort of all candidates. Because each peer runs on its own reader thread, one connection can hold the lock nearly continuously on a large torrent and serialize every other peer and the maintenance tick behind it. The exact cost needs a benchmark; the shape is clear from the code.
*Fix:* skip `is_complete` via the existing `done` flag; keep an incremental wanted-and-missing counter in the picker; accept bitfield/have-all/have-none only as the first message and drop the peer on repeats; release the lock around storage I/O and verification; incremental rarest-first buckets instead of a per-pick sort.

**M-11. Choker optimistic slot never reaches some peers when the candidate count is a multiple of 3.**
`crates/clove-core/src/choker.rs:110,130`.
`optimistic_round = round % 3 == 0` and `idx = round % candidates.len()`. When `round ≡ 0 (mod 3)` and `len ∈ {3, 6, 9, …}`, `idx` cycles through only `len/3` values. With a stable candidate order (a fresh seeder, or a leecher given M-12) some peers are never unchoked, ever. Confirmed by simulation over slots 1, 2, 4 and every candidate count up to 12: starvation at every multiple of 3, none elsewhere. Both fairness tests happen to use candidate counts of 4 and 2.
*Fix:* `idx = (round / 3) % len`, or a separate optimistic counter; sweep candidate counts 1..=12 in the model test.

**M-12. Choker "rate" is lifetime bytes *we uploaded to* the peer, in both roles.**
`crates/clove-core/src/torrent.rs:1474-1483`; `crates/clove-core/src/choker.rs:9-11`.
`Peer` has no download counter and the snapshot uses `p.uploaded`. While leeching we reward peers we have given the most to rather than those giving to us, and because the counter is cumulative and never decays, early unchokes entrench permanently. Contradicts the module doc.
*Fix:* per-peer downloaded counter, windowed per-round rates, pick by role.

**M-13. Interest flapping runs a full choke round per 5-byte message and lets a peer drive the optimistic rotation.**
`crates/clove-core/src/torrent.rs:1112-1119`; `crates/clove-core/src/choker.rs:109`.
Every `Interested`/`NotInterested` calls `run_choker` and advances `round`. Every third toggle reassigns the optimistic slot, choking an honest peer (which discards its outstanding requests) and unchoking another.
*Fix:* on `Interested`, run a round only if a slot is free or the interval elapsed; otherwise leave it to the periodic tick.

**M-14. A failed block write leaks the picker's in-flight count and is silent.**
`crates/clove-core/src/torrent.rs:1285,1295`; `crates/clove-core/src/storage.rs:52`.
The peer's `in_flight` entry is removed, then `write_block(...).is_ok()` is tested and the `Err` arm does nothing: no `picker.block_failed`, no error surfaced. On `ENOSPC` without preallocation, or `EIO`, the block is never re-offered outside endgame; the download stalls permanently in release and trips `debug_check_state` in debug. Relatedly, a verify *I/O error* is treated as a hash failure (line 1309), so a bad sector re-downloads the piece forever.
*Fix:* call `block_failed` on error and record a storage error on the torrent (surface in status, pause it). Distinguish `Err(io)` from `Ok(false)` in verification.

**M-15. Every file of every hosted torrent is opened at once, and metainfo caps neither file count nor piece count.**
`crates/clove-core/src/storage.rs:58-82,381-395`; `crates/clove-core/src/metainfo.rs:425-460`; `crates/cloved/src/registry.rs:198,769`.
A `.torrent` with tens of thousands of entries exhausts `RLIMIT_NOFILE` (the units pin 8192), taking the SAM sockets with it. Operator-added input, but `SECURITY.md` declares `.torrent` a hostile surface.
*Fix:* cap file count in `MetaInfo::parse`; open lazily; skip priority-0 files.

**M-16. A panicking reader thread leaks its peer entry, budget slot, and writer thread; the poisoned state lock is recovered and reused.**
`crates/clove-core/src/torrent.rs:130-132,891-907`.
`remove_peer` runs only on normal exit (contrast `PendingGuard` in `swarm.rs`). Every lock site uses `PoisonError::into_inner`, so a panic mid-mutation leaves a half-updated `State` every other thread keeps using. Recovery depends on the 300 s idle timeout in the maintenance tick.
*Fix:* a drop guard in `spawn_reader` that calls `remove_peer`; consider making a poisoned state lock fatal for that torrent.

**M-17. Endgame issues duplicate requests to every peer and never cancels.**
`crates/clove-core/src/picker.rs:442-445`; `crates/clove-core/src/wire.rs:157`; `crates/clove-core/src/torrent.rs:1087,1292-1295`.
`Cancel` is parsed and ignored but never constructed. With 50 peers and the 32-block threshold that is up to 800 requests for 32 blocks, about 12.5 MiB of duplicate transfer per torrent tail over I2P. Duplicate copies for an unverified piece overwrite earlier ones, so one bad copy forces a full re-download (interacts with H-3).
*Fix:* on first arrival, send `Cancel` to the other peers holding that block in flight; drop later duplicates.

**M-18. `std::thread::spawn` is used where exhaustion panics, with different consequences per thread.**
`crates/cloved/src/main.rs:239,394,481,501,719`; `crates/cloved/src/registry.rs:787-811`; `crates/clove-core/src/swarm.rs:103,205`; `crates/clove-core/src/torrent.rs:552`.
Only per-peer threads use `Builder`. The units set `TasksMax=1024`; peers cost two threads each times `peer_limit` 200, plus three per live torrent, one per API connection, one per scan. A spawn panic on the main thread exits the daemon; in the supervisor thread it dies silently with `router` stuck at "connected" and no reconnect ever; inside `start_live` it unwinds holding the registry mutex and leaves a `Hosted` registered with the demux but with `live: None`.
*Fix:* `Builder::new().spawn()` and handle `Err` everywhere; cap API handler threads; note the `TasksMax` arithmetic in the unit.

**M-19. (Needs confirmation) The user unit has an ordering cycle.**
`contrib/systemd/user/clove.service:18,53`.
`After=default.target` together with `WantedBy=default.target`. A target adds `After=` on every unit it `Wants=`, so this is a cycle; systemd breaks it by deleting a job, possibly clove's, and logs "Found ordering cycle". `enable --now` may work while login-time start does not.
*Fix:* delete the `After=` line (user units already order after `basic.target`); verify with `systemd-analyze --user verify`.

**M-20. bencode has no node-count budget, and `MetaInfo::parse` decodes the input twice.**
`crates/clove-core/src/bencode.rs:171,256-263`; `crates/clove-core/src/metainfo.rs:171-179,191,202`; `crates/clove-core/src/metadata.rs:369`.
Every 2-byte `le`/`de` becomes a 32-byte `Value` plus `Vec` growth (about 16× amplification), and `raw_entry` decodes again while the first tree is alive. Bounded by the input caps, so not unbounded, but a single peer can push a pending magnet to roughly 2 × 128 MiB transient via an 8 MiB `ut_metadata` payload, on a project that otherwise budgets memory carefully.
*Fix:* give the decoder a total-node budget (e.g. `input.len()`); have `raw_entry` return the span from the single pass; consider lowering `MAX_METADATA_SIZE` (1 MiB already covers ~50k pieces).

**M-21. Local API: no read timeout, one unbounded thread per connection, full body read before authentication.**
`crates/cloved/src/main.rs:715-748`; `crates/clove-core/src/http.rs:209-226,497-498`; `crates/i2pnet/src/api.rs` (no `set_read_timeout`).
A client that connects and never sends parks a thread forever, and 2 MiB may be buffered per unauthenticated connection. The socket is `0600`, so only the same user (or root) reaches it, which `SECURITY.md` puts out of scope; a crashed client leaving a half-open connection is the realistic case. Low on its own; listed as Medium because it compounds with M-2 and M-18.
*Fix:* `set_read_timeout(Some(10s))` on the accepted stream; a small cap on handler threads; check the token header before reading the body.

### 3.3 Low

**L-1. Router text reaches errors and logs unscrubbed on three paths.** `crates/i2pnet/src/sam.rs:179,309-313,1208`. `HELLO REPLY`, `STREAM STATUS` and the `RESULT=` word of `NAMING REPLY` are formatted raw; a `\x1b[2J` or `\r` in them repaints the terminal or forges a log line. `sam_hello` also matches `RESULT=OK` as a substring anywhere in the line, so `RESULT=NOVERSION MESSAGE="RESULT=OK"` passes. *Fix:* route all three through `scrub_control_line`; parse `RESULT=` as a token.

**L-2. The naming negative-cache error repeats the hostile name raw, and `InvalidInput` names are cached at all.** `crates/i2pnet/src/naming.rs:84-95,114-131`. `check_lookup_name` refuses and scrubs, but the `Err` is cached as a `Miss`, so the second lookup within 30 s formats the unvalidated name into stderr and the API error text. *Fix:* do not cache `InvalidInput`; scrub `name` in the message.

**L-3. Naming cache is unbounded and never evicts; a concurrent `Miss` can overwrite a fresh `Hit`.** `crates/i2pnet/src/naming.rs:46,105-133`. Growth is bounded by what the operator adds. *Fix:* cap entries; on `Err`, only insert a `Miss` if the current entry is not a `Hit`.

**L-4. `bind_unix`: mode is set after bind, `chmod` follows symlinks, stale removal is unconditional.** `crates/i2pnet/src/api.rs:30-36`. The socket is briefly `0777 & ~umask` before `set_permissions`; `set_permissions` is `chmod(2)` and follows a swapped-in symlink if the socket directory is shared (the man page's `/run/clove/clove.sock` example). The default `$XDG_RUNTIME_DIR` is `0700`, so not exposed by default. See also M-3. *Fix:* bind in a fresh private `0700` directory and `rename` into place, or set `umask(0o177)` around the bind while single-threaded.

**L-5. Crate-wide `#![allow(clippy::disallowed_methods)]` in i2pnet also silences the unbounded-channel ban.** `crates/i2pnet/src/lib.rs:24`. The allow exists for the socket exception but covers both banned methods for the whole crate. No violation today (`mpsc::channel` appears only in tests). *Fix:* keep `disallowed_methods` denied crate-wide; allow it on test modules only.

**L-6. `ReconnectPolicy::jittered` panics on a NaN `jitter`.** `crates/i2pnet/src/supervisor.rs:274-285`. The NaN guard covers `roll` but `clamp` passes NaN through and `Duration::mul_f64` panics. `jitter` is `pub`; only `Default` produces it today. *Fix:* guard `is_nan()` on `jitter` too.

**L-7. `nickname` and `persistent_key` enter SAM command lines without validation inside i2pnet.** `crates/i2pnet/src/sam.rs:218-221,601-606,906-909`. Safe today (the nickname generator emits `[a-z0-9-]`, and `cloved` refuses a key that is not pure base64), but `SamConfig` is `pub` and `check_lookup_name` states the rule that this crate does not trust its callers. *Fix:* reject bytes `<= 0x20` or `0x7f` in `SamSession::connect`.

**L-8. `text::scrub` misses most `Cf` and the line/paragraph separators.** `crates/clove-core/src/text.rs:273-279`; twin at `crates/i2pnet/src/sam.rs:797-806`. Covered: `Cc`, LRM/RLM, U+202A–202E, U+2066–2069. Not covered: U+061C (a `Bidi_Control`), U+200B–200D, U+2060, U+FEFF, U+00AD, U+2028/2029, U+180E, tag characters, variation selectors. A name like `safe\u{200B}.exe` cannot be matched by typing. *Fix:* add a short explicit `Cf` range table to both scrubbers and a test pinning them equal.

**L-9. JSON encoder leaves DEL, C1 controls, and U+2028/2029 unescaped; `clove --json` prints the body verbatim.** `crates/clove-core/src/json.rs:518-521`; `crates/clove/src/main.rs:341,354,457,711-714`. U+009B is a one-character CSI that xterm-family terminals honour in UTF-8 mode. The comment claiming `--json` consumers "were never affected" is true for C0 only. *Fix:* emit `\u00XX` for `0x7f..=0x9f` and for U+2028/2029 (still valid JSON).

**L-10. Torrent path components reach stderr unscrubbed through `io::Error`.** `crates/clove-core/src/storage.rs:373-378`; surfaces at `crates/cloved/src/registry.rs:638`, `crates/cloved/src/main.rs:241,532-535`. `refused()` embeds the raw component; `check_component` allows ESC, C1, and bidi. A component `"\x1b]0;pwned\x07"` under a symlinked parent logs a title-changing escape on every start. Contradicts the scrubbed-log guarantee. *Fix:* `text::scrub(component)` inside `refused`.

**L-11. Tracker `interval` has a floor but no ceiling; `min interval` is parsed and unused.** `crates/clove-core/src/tracker.rs:214-216,246-254,415-416`. `interval: 4000000000` means never re-announce until restart. *Fix:* clamp to a ceiling (e.g. 4 h); use or drop `min_interval`.

**L-12. No cap on the number of announce URLs a torrent or magnet keeps.** `crates/clove-core/src/metainfo.rs:461-500`; `crates/clove-core/src/magnet.rs:78-83`; `crates/clove-core/src/swarm.rs:180,335-355`. A 2 MiB `.torrent` with ~50k `.i2p` URLs makes the announcer spend days per cycle and the router do 50k naming lookups. *Fix:* keep at most ~16 across tiers, count the rest as skipped.

**L-13. Path components have no length cap; collisions on case-folding or normalising filesystems.** `crates/clove-core/src/metainfo.rs:518-530,534-546`. `ENAMETOOLONG` surfaces far from its cause; `A.txt` vs `a.txt` (or NFC vs NFD) is the intra-torrent aliasing `check_distinct_paths` exists to refuse. *Fix:* refuse components > 255 bytes; compare case-folded (ideally NFC) paths, or document the filesystem assumption.

**L-14. HTTP number parsing accepts a leading `+`; the response side keeps the last of conflicting `Content-Length`s.** `crates/clove-core/src/http.rs:172-179,270,479-481`. Nil impact today (no keep-alive, no proxy, I2P-only trackers); the kind of leniency that becomes a smuggling primitive later. *Fix:* require all-digits; refuse conflicting duplicates on responses as requests already do.

**L-15. Metadata request serving has no per-peer rate limit.** `crates/clove-core/src/torrent.rs:1198-1200,1238-1268`. Bandwidth amplification only (~16 KiB out per ~30-byte frame in); memory is bounded by the outgoing queue. *Fix:* per-peer budget per interval, `Reject` past it.

**L-16. `DELETE ?data=1` during a running scan recreates the files it deleted.** `crates/cloved/src/registry.rs:1368-1415,1329-1332`. `remove` does not check `scanning`; the unlocked `ScanJob` reopens with `O_CREAT` (and `fallocate`s under `preallocate yes`), then `finish_scan` returns `NotFound` and the orphaned tree stays. *Fix:* refuse `remove` while scanning, or re-run deletion on `NotFound`.

**L-17. Pending-magnet removal ordering is the reverse of the hosted path.** `crates/cloved/src/registry.rs:1373-1377`. In-memory entry removed before the file; on unlink failure the API says 500 but the magnet reappears at restart. *Fix:* delete the file first.

**L-18. User-typed torrent references are interpolated into the request target unencoded.** `crates/clove/src/main.rs:435-568`. `clove remove 'abcd?data=1'` deletes data without `--data`. CR/LF/NUL are refused by `Request::encode`, so no header injection. *Fix:* validate references client-side (`[0-9a-f]{4,40}` or an index).

**L-19. One daemon-supplied string is printed without `display()`.** `crates/clove/src/main.rs:410`. `println!("added {info_hash}")` is the only place a daemon string bypasses the scrubber; today it is always hex. *Fix:* `display(info_hash)`.

**L-20. Relative XDG variables are accepted.** `crates/clove-core/src/config.rs:40-62`. The spec says relative values must be ignored; config keys are validated absolute but `XDG_DATA_HOME=foo` makes the data dir and the Landlock rule cwd-relative. *Fix:* apply `absolute()` in `from_env`, fall back to the `$HOME` default.

**L-21. No signal handling; clean-stop semantics undocumented.** No `SIGTERM`/`SIGINT` handler exists. State stays consistent (atomic writes), but up to 30 s of verified progress is re-hashed, the `stopped` announce is never sent, and the socket file is left behind. `man/cloved.8` does not say so. *Fix:* a minimal handler that persists and detaches, or document the trade-off.

**L-22. System unit: root must pass `-c /etc/clove/clove.conf` to every `clove` call, and this is undocumented.** `contrib/systemd/system/clove.service`; `crates/clove/src/main.rs:1159-1168`. `clove` resolves config from `$XDG_CONFIG_HOME`, never `@SYSCONFDIR@`; under `DynamicUser` only root can read the token anyway. `ReadWritePaths=/var/lib/clove` (line 66) is redundant with `StateDirectory=` and names the symlink the comment just below explains. *Fix:* a comment and example in the unit and `clove.1`; drop or annotate line 66.

**L-23. Any shape-valid block, unsolicited included, resets `strikes`.** `crates/clove-core/src/torrent.rs:1285-1288`. A peer can hold a slot and 16 in-flight blocks indefinitely without answering a request, at 16 KiB per maintenance tick. *Fix:* reset only when `was_requested`.

**L-24. No self-connection guard.** `crates/clove-core/src/swarm.rs:397,550-555`; `crates/clove-core/src/torrent.rs:749-756,779-784`. Trackers routinely echo the announcer; nothing filters `local_dest` from the sweep or compares `peer_id` on handshake. Result: two idle connections to ourselves per torrent, and PEX then advertises our own destination. Needs confirmation that the router permits a self-dial. *Fix:* drop on `theirs.peer_id == ours`; filter `local_dest` in the sweep.

**L-25. Storage's traversal defence is symlink-only; lexical safety is entirely metainfo's.** `crates/clove-core/src/storage.rs:343,349`. Components go straight to `mkdirat`/`openat`; a `..` component *would* walk up. `metainfo::check_component` is the only guard, and the module's own doc invokes "no layer assumes another". *Fix:* re-check components in `walk_beneath` (three lines).

**L-26. 32-bit `usize` overflow on a peer-supplied `ut_metadata` piece index.** `crates/clove-core/src/torrent.rs:1246`; `crates/clove-core/src/metadata.rs:154,495`. `piece as usize * METADATA_PIECE_LEN` panics in debug and wraps in release on 32-bit targets. 64-bit is unaffected and the project targets 64-bit only. *Fix:* `checked_mul`.

**L-27. Protocol leniencies that feed M-10.** Invalid bitfields are ignored rather than the peer dropped (`torrent.rs:1131` vs `bitfield.rs:6-7`); BEP 6 messages are honoured though fast is never advertised (`torrent.rs:724-727,1086-1090,1136-1143`); the bitfield is not guaranteed to be the first message we send (`torrent.rs:825-838`), which strict clients disconnect on; dropped peers stay `Trusted` and are re-dialled after a flat 30 s with no escalation (`swarm.rs:590-593`); per-torrent `max_peers` is advisory on the inbound path (`swarm.rs:762-765`); `remove_beneath` creates the directory tree it is asked to delete from (`storage.rs:436-444`).

### 3.4 Info

- **I-1.** Extension handshake and tracker user-agent disagree: `client: "clove/0.1"` at `torrent.rs:976,1609`, `extension.rs:126`, `http.rs:569` versus `USER_AGENT = "clove/2026.08"` at `tracker.rs:32`. Use `crate::VERSION` in all of them.
- **I-2.** `[::1]:7656` and `localhost:7656` are accepted by config and documented in `clove.conf(5)`, but `sam_tcp_port` drops the host and the dial is always `127.0.0.1`. Not a leak (there is no address type to carry anything else), but a router bound only to `::1` is unreachable while the config validator says the address is fine. Either refuse `[::1]` or add an IPv6-loopback flag.
- **I-3.** The `STREAM FORWARD` control socket is held but never read (`sam.rs:875-878,920`). If Java I2P pings the forward socket the way it pings the session socket and drops it on `PONG timeout`, forwarding would stop with the session still "healthy". Could not be verified from this repository.
- **I-4.** Zeroization of key material is not considered (`sam.rs:103,150,358,572,601-618`). `SECURITY.md` puts a compromised account out of scope and the units set `LimitCORE=0`; note it as a deliberate non-goal or adopt `zeroize`.
- **I-5.** `persist_progress` holds the registry lock while `fsync`ing every file of every live torrent every 30 s, and `start_live` holds it across `fallocate` of a whole torrent (`registry.rs:769-773,918-945`). No deadlock (lock order traced: registry → torrent internals, `router` never nested), but every API call stalls for the duration under disk load.
- **I-6.** Startup spawns one hashing thread per torrent needing re-verification (`main.rs:236-244`): N concurrent full-disk reads after an unclean stop.
- **I-7.** A test asserts a string the code can never emit: `main.rs:1580-1583` checks the reply does not contain "exceeds the allowed size", but `handle` maps every parse error to "malformed request". Passes vacuously. Map `BodyTooLarge` to its own message.
- **I-8.** `expand --all` excludes `fetching-metadata` even for `remove`, so `clove remove --all` leaves magnets behind (`clove/src/main.rs:218`).
- **I-9.** No thread is named (`torrent.rs:552,918-920`; `swarm.rs:99,103,205,243,705,729`). Cheap and useful in a `ps -T` or a core.
- **I-10.** `Message::parse` copies bitfield/piece/extended payloads the frame buffer already holds (`wire.rs:155,171,185`), and `write_message` allocates a fresh `Vec` per message (`wire.rs:431-433`). Bounded; churn only.
- **I-11.** `BLOCK_LEN` is a hard 16 KiB (`wire.rs:25,276`); a client requesting 32 KiB blocks is disconnected (`torrent.rs:902`). Interop, not security.
- **I-12.** `MAX_MESSAGE_LEN` 1 MiB means torrents over ~8.39M pieces can never exchange bitfields, and metainfo does not cap piece count. Edge case.
- **I-13.** Small casts and arithmetic worth a comment, none reachable: `addr.rs:93` `c as u8`; capacity arithmetic at `addr.rs:119,154,217`; `Instant::now() + timeout` at `sam.rs:174,228,610,911,1232` with non-configurable timeouts.
- **I-14.** `json.rs:452-500` accepts `01`, `1.`, `-.5`; `magnet.rs:64-73` lets the last of several `xt=` win silently; `parse_priorities` accepts `+1`. Lenient, not unsafe.
- **I-15.** `write_private_file` and `atomic_write` leave `*.tmp` files behind after a crash; `chaos.sh` proves they are ignored. Clutter only.
- **I-16.** `data_dir` is created with the umask and then chmod'd `0700` (`main.rs:180-195`): a brief `0755` window on first run before any secret exists.
- **I-17.** `clove.bash` uses unquoted `$(compgen …)` in array assignment; filenames with glob characters expand. No completion script contacts the daemon or evaluates its output.
- **I-18.** `deny.toml` allows `BSD-2-Clause` which nothing uses, and `landlock` pulls two `syn` majors. Cosmetic.

## 4. Code quality

The engineering standards in `docs/SCOPE.md` §9 are not aspirational: they are enforced and they show.

- **Lint posture.** `unsafe_code = "forbid"`, `missing_docs = "deny"`, `clippy::all` and `clippy::pedantic` at deny, `unwrap_used`/`expect_used` denied outside tests, `disallowed_types` banning every `std::net` type outside `i2pnet`, `mpsc::channel` banned in favour of bounded channels. Eleven `#[allow]`s in non-test code, each with a stated reason (float casts, a dispatch table, the one crate-level socket exception). Toolchain pinned to `1.94.1` so lint results are reproducible.
- **Error handling.** Small hand-written error enums per module, no `anyhow`, error text written for an operator. Every mutex poison is handled (though see M-16 for whether ignoring it is right).
- **Documentation.** Module docs explain *why*. The seccomp allowlist is measured from a trace and every entry not in the trace carries its justification in place (`sandbox.rs:322-433`). The Landlock role withholds rights by name and the test asserts each absence. Man pages are lint-checked in CI.
- **Tests.** 384 tests, a hostile-input mutation sweep on every push, ten libFuzzer targets with dictionaries and a committed seed corpus, an evil-peer suite (slow-loris, stop-reading, PEX flood, table monopolisation, straddling requests), an adversarial API suite over a real socketpair, and three end-to-end scripts including a crash-storm harness and a fake SAM bridge that traces the syscall filter. The gaps are listed in §6.
- **Dependencies.** Five direct runtime dependencies, each justified in `DEPENDENCIES.md`; 32 crates locked; `cargo deny` and a socket-capable-crate grep in CI; hand-rolled bencode, JSON, HTTP/1.1, config, and argument parsing rather than frameworks.
- **Weak spots.** The engine's single per-torrent mutex is held across disk I/O and O(pieces) scans (M-10); the choker has two correctness defects (M-11, M-12); error paths in the accept loops and the block-write path are the least exercised code and where most Medium findings live; thread creation is unchecked (M-18); `std::thread::spawn` threads are unnamed (I-9).

## 5. What is done well

Worth stating explicitly, because it is what makes the findings above the whole list rather than the tip of one.

- **Loopback is enforced by type, not by check.** `SamConfig` carries only a `u16` port; every connect is `TcpStream::connect_timeout(&SocketAddr::from((Ipv4Addr::LOCALHOST, port)))` and the inbound listener binds `(Ipv4Addr::LOCALHOST, 0)`. There is no string address and no `ToSocketAddrs` call, so there is no DNS path at all. `localhost` in the config is never resolved.
- **Every SAM read is bounded in bytes and time.** `read_sam_line` has a per-exchange byte cap *and* an `Instant` deadline, which defeats the dribble attack a per-read timeout alone does not, and the fake-bridge suites prove every misbehaviour fails in bounded time for HELLO, SESSION CREATE, STREAM CONNECT and NAMING LOOKUP.
- **Private-key handling is careful.** `SamSession` has no `Debug`; the public destination is cut from the blob by certificate length rather than a constant; `scrub_control_line` redacts named secret fields *and* any 64+ character base64 run and is applied on the way *into* `Life::last_line`, so no later use can forget it. In `cloved`, the key and token are `create_new` + `0600` + fsync + rename in a `0700` directory, loaded with `O_NOFOLLOW` and `fstat` on the held descriptor, and a world-readable secret is refused rather than silently repaired.
- **The bencode decoder is genuinely strict.** Depth limit, `checked_*` integer accumulation that round-trips `i64::MIN`, `i-0e` and leading zeros refused, string lengths validated against remaining input before allocation, duplicate keys refused, and `raw_entry` guaranteeing the info-hash covers the exact input bytes.
- **One tracker URL parser** is shared by the filter and the announce builder, checks `.i2p` by last *label*, refuses userinfo, fragments, control bytes, bad ports, empty labels and malformed escapes, and `Request::encode` independently refuses CR/LF/NUL. `announced_url` redacts `ip=` by name; no redirects are followed.
- **Path handling is kernel-enforced.** Every component is an `openat(O_NOFOLLOW|O_DIRECTORY)` on a directory descriptor, in both the write and the delete direction, so a symlink fails the syscall rather than a check made a moment earlier.
- **Resume files** are version-gated both ways, refuse unknown keys, check bitfield length and spare bits, enforce `verified ⊆ have`, publish only `verified`, and rescan the gap. Writes are temp + fsync + rename + directory fsync.
- **The wire layer** bounds the declared length before allocating, validates request ranges against the *piece* rather than merely the torrent, rejects unsolicited, duplicate, late and post-verification blocks before a byte reaches disk, and withdraws availability before re-adding so repeated bitfields cannot inflate rarity. Every send is `try_send` on a bounded channel; a full queue drops the peer; a `closer` unblocks a stuck reader.
- **The sandbox** is an allowlist with four calls narrowed by argument (`socket` to `AF_INET`/`SOCK_STREAM`, `ioctl` to `FIONBIO`, `mmap`/`mprotect` to W^X), measured from a trace, tested under the live filter in CI, reported in `GET /v1/status`, and optionally required. Landlock grants 8 of 16 rights with each absence justified. Confinement runs before any thread is spawned.
- **The API** authenticates before routing on every path and method, compares in constant time against a shape-checked expected value, refuses ambiguous HTTP framing rather than guessing, and never joins an info-hash to a path.
- **Concurrency is simple.** No nested-lock inversions anywhere; the session life has one mutex released before `notify_all`; scans and hashing run with the registry unlocked; backoff arithmetic is overflow-proof and jitter only shortens.

## 6. Test gaps

Tests that would have caught the findings above and are cheap to add:

1. One destination holding the pending-handshake cap *while* an honest peer connects (H-1).
2. A dribbling handshake versus sweep duration and `shutdown` time (H-2).
3. Liar plus honest peer attached concurrently, with a bound on bytes-to-completion (H-3).
4. `accept()` returning `EMFILE` on both listeners (M-1, M-2).
5. Two daemons on one `data_dir` (M-3).
6. A refused `destination.key` surviving `remember()` (M-4).
7. `format!("{config:?}")` not containing the key (M-5).
8. A private torrent never advertising or accepting PEX (M-8).
9. Two torrents with the same `name` (M-9).
10. Choker fairness swept over candidate counts 1..=12 (M-11).
11. The block-write error path (M-14).
12. Interest flapping's effect on other peers (M-13).
13. Per-message cost on a large-piece-count torrent (M-10).
14. Self-connection (L-24); `remove_beneath` on an absent layout (L-27).
15. `--json` output containing U+009B (L-9); a component containing ESC surfacing in a log (L-10).
16. The API oversized-body test asserting the parser's real message (I-7).

## 7. Recommended order of work

1. **H-3, H-1, H-2** together: they share a fix shape (attribution and a per-run ban set; absolute deadlines on handshakes; per-destination pending count). This closes the "one peer takes over a torrent" gap that `SECURITY.md` promises is closed.
2. **M-1, M-2, M-18**: make every accept loop and every thread spawn survive resource exhaustion. Small diffs, and they turn three silent failures into logged ones.
3. **M-3, M-4, M-5**: the instance lock, preserving a refused key, and redacting `Debug` on `SamConfig`. Each is under an hour and each is the kind of thing that hurts a real user once.
4. **M-8, M-9**: honour `private`; refuse duplicate names.
5. **M-11, M-12, M-13, M-14, M-17**: the choker and block-path defects. These affect swarm health more than security.
6. **M-10**: the lock-scope work. Larger; benchmark first.
7. The Low list, roughly in order. L-8, L-9, L-10 close the remaining gaps in the scrubbed-output guarantee and are mechanical.
8. Update `SECURITY.md` with M-7 (the forward port on multi-user hosts) and I-2 (`[::1]` is dialled as `127.0.0.1`) as known limitations, or fix them.
